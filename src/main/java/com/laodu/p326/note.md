# Java 泛型：形参与实参判断体系（从零到一笔记）

> **术语约定**：本文为教学方便，把“类型实参”限定为“具体类型或推断出的具体类型”。严格来说，JLS 中类型变量也可以作为 type argument；本文按“填充物身份”分类，避免把“形参引用”误叫成“类型实参”。

---

## 0. 总纲一句话

> **声明头里“引入名字”的是形参；使用处尖括号里“填东西”的是实参槽位；槽位里填具体类型是类型实参，填已声明的形参名字是形参引用。**

三层结构记住这个体系：**位置 → 槽位 → 填充物身份**。

---

## 1. 概念地基：形参 vs 实参

### 1.1 最形象的类比

泛型的形参/实参，就是普通方法参数机制的“类型版本”：

| 普通方法 | 泛型 |
|---|---|
| `void f(int x)` 声明参数 `x` | `class Box<T>` 声明类型参数 `T` |
| `f(5)` 传入实参 `5` | `Box<String>` 传入类型实参 `String` |
| 方法体内用 `x` | 类体内用 `T` |
| `x` 是“变量名”，等待赋值 | `T` 是“类型占位符”，等待填实参 |

**关键结论：**

- **形参 = 占位符 / 变量名**，本身不是具体类型。
- **实参 = 真正填进去的值 / 类型**。
- 形参要能“被引用”，实参要能“被填入”。

### 1.2 三个身份（不只是两个！）

很多人以为只有“形参 / 实参”两种，实际判断时要分**三种身份**：

| 身份 | 含义 | 例子 |
|---|---|---|
| **形参声明** | 在某处**新引入**一个类型变量 | `class Box<T>` 里的 `T` |
| **形参引用** | 引用一个**已声明过**的形参 | `class Box<T> { List<T> list; }` 里的 `T` |
| **类型实参** | 填入一个**具体类型**（本文分类下） | `Box<String>` 里的 `String` |

这就是“填在实参槽位的形参”的根源：**位置是实参槽位，但填充物身份是形参引用**。

## 2. 声明：形参诞生的唯一途径

### 2.1 只有 4 处声明头

类型形参只能在**声明头**里诞生，共 4 处：

```text
① 泛型类        class  Box   <T> { ... }        ← <T> 在类名后
② 泛型接口      interface  Repo <T> { ... }      ← <T> 在接口名后
③ 泛型方法      <T>  T  foo(T x) { ... }        ← <T> 在返回类型前
④ 泛型构造器    <T>  Box(T t) { ... }           ← <T> 在构造器名前
```

补充：

- **记录（record）**也可以：`record Point<T>(T x, T y) {}`，同类的规律（名字后）。
- **枚举不能**声明类型形参：`enum E<T>` 编译错误。
- **匿名类不能**声明类型形参。

### 2.2 位置规律表（易混点）

| 声明对象 | `<T>` 相对名字的位置 |
|---|---|
| `class` / `interface` / `record` | **名字之后** |
| 方法 | **返回类型之前**（即方法名之前） |
| 构造器 | **构造器名之前** |

⚠️ 不能笼统说“类名和方法名处”，方向相反。

### 2.3 声明头 vs 类体：`T` 的两种身份

```java
class Box<T> {          // ← T 是“形参声明”（诞生处）
    T value;            // ← T 是“形参引用”（类体内使用）
    T get() { ... }     // ← T 是“形参引用”
}
```

**判断规则：**

- 在**声明头**的尖括号里 → **形参声明**（新引入）。
- 在**声明头以外的普通位置**出现的同一个 `T` → **形参引用**（使用已有形参）。
- 注意：方法/构造器声明头可以再声明自己的类型形参，见 §11.9。

## 3. 使用：实参槽位的出现

### 3.1 槽位的定义

在**类型使用处**，任何“类型名 + 尖括号”的地方，尖括号就是实参槽位；**声明头除外**。

```text
Box< ______ >
     ↑
   实参槽位
```

只要在代码中使用 `类型名<...>`，就是“使用”这个泛型类型。**使用 ≠ 一定填具体类型**——这是最容易懵的地方。

### 3.2 槽位里能填的 4 类填充物 + 1 种特殊空槽

| 填充物 | 例子 | 身份 |
|---|---|---|
| ① 具体类型 | `Box<String>` | 类型实参 |
| ② 形参引用（可见的类型变量） | `Box<T>` | 形参引用 |
| ③ 通配符 | `Box<?>`、`Box<? extends Number>` | 通配符实参 |
| ④ 嵌套参数化类型 | `Box<List<String>>` | 外层是实参槽，内层递归判断 |

**特殊空槽：** `new Box<>()` 里的 `<>` 不是普通类型槽位的填充物，它只出现在构造器调用中，由目标类型推断类型实参。  
`Box<> d;` 这种变量声明是**非法**的。

**核心理念：槽位是位置，填充物身份各有不同。**

## 4. 判断流程（核心方法）

### 4.1 两步法

```text
第 1 步：看尖括号“在哪里”
   ├─ 在声明头 → 形参声明
   └─ 在其他地方（类型名后、方法名后）→ 实参槽位
              ↓
第 2 步：看槽位里“填什么”
   ├─ 具体类型（String / Integer / MyClass）→ 类型实参
   ├─ 大写字母 T / E / K / V → 形参引用（若能追溯到某个声明）
   ├─ ? / ? extends X → 通配符实参
   ├─ 类型名<...> → 递归判断（嵌套）
   └─ 空 <>（仅构造器调用）→ 推断实参
```

### 4.2 判断决策树

```text
看到  名字<填充物>
       │
       ├── 名字是 class / interface / record？且尖括号紧跟其后？
       │        └── 是 → 形参声明
       │
       ├── 名字是方法 / 构造器？且尖括号在返回类型 / 名字之前？
       │        └── 是 → 形参声明
       │
       └── 其他情形 → 实参槽位，看填充物：
                │
                ├── 具体类型 → 类型实参
                ├── 大写字母 → 形参引用（追溯声明来源）
                ├── ? 系列 → 通配符实参
                ├── 嵌套 <...> → 递归
                └── 空 <>（仅构造器调用）→ 推断实参
```

### 4.3 一段代码走完全流程

```java
class Pair<A, B> {                          // ① A、B 是形参声明

    Map<A, List<B>> map;                    // ② A、B 是形参引用；
                                            //    Map 槽位填 A、List<B>；
                                            //    List 槽位填 B

    <C> C pick(A a, C c) {                  // ③ C 是形参声明（方法级）
        Pair<A, C> p;                       //    槽位填 A（形参引用）和 C（形参引用）
        return c;
    }
}

class Main {
    void use() {
        Pair<String, Integer> p;            // ④ 槽位填 String、Integer → 类型实参
        Map<String, List<Integer>> m;       // ⑤ 外层槽位填 String、List<Integer>
                                            //    内层 List 槽位填 Integer
        Pair<?, ?> w;                       // ⑥ 通配符实参
        new Pair<>();                       // ⑦ 空槽，推断实参
    }
}
```

## 5. 重点对比：`Box<T>` vs `Box<String>`

这是理解整个体系的**分水岭**：

```java
class Box<T> {                 // T 在这里诞生（形参声明）
    List<T> list;              // 使用 List，槽位填 T（形参引用）
}

class Main {
    Box<String> b;             // 使用 Box，槽位填 String（类型实参）
}
```

**对比：**

```text
List<T>       ← 使用 List，实参槽位里装“形参引用 T”
Box<String>   ← 使用 Box ，实参槽位里装“具体类型实参 String”
```

### 5.1 为什么 `Box<T>` 里的 `T` 不算实参？

因为 `T` 是**上面的 `class Box<T>` 声明头里诞生的形参**，此处只是**引用它**。它不是“具体类型”，只是“形参的代言人”。

### 5.2 场景分工（修正版）

| 场景 | 槽位里可能填什么 |
|---|---|
| 泛型声明**内部** | 可以填形参引用（`T`、`E`、`K`、`V`），也可以填具体类型、通配符、嵌套类型；身份看填充物来源 |
| 泛型声明**外部**（普通代码） | 通常填具体类型实参、通配符、嵌套类型；若外部代码本身也有类型形参，也可填形参引用 |

**关键点：** 泛型声明内部**不是“只能”填形参引用**。例如：

```java
class Bag<T> {
    List<String> names;             // String 是类型实参
    Map<T, List<String>> index;     // T 是形参引用，String 是类型实参
}
```

声明内部用形参占位，是因为不知道最终实参是什么；但具体类型、通配符、嵌套类型同样可以出现。

## 6. 嵌套递归：槽位套槽位

嵌套时**逐层递归判断**：

```java
Map<String, List<Integer>> m;
```

展开图：

```text
Map<_____, List<Integer>>
     │      │
     │      └── 嵌套参数化类型 List<Integer>
     │              │
     │              └── 具体类型实参 Integer
     │
     └── 具体类型实参 String
```

**要点：** 每一层尖括号都是独立的实参槽位，各自判断，不互相影响。

```java
class Triple<X> extends Pair<X, String> { ... }
//                          ↑   ↑
//                   形参引用X   具体类型实参String
//                  （槽位1）    （槽位2）
```

**同一行内可共存“形参引用”和“具体类型实参”** —— 因为每个槽位独立判断。

---

## 7. 通配符：实参位置的特殊填充物

通配符**只能出现在实参槽位**，不能出现在声明头：

```java
class Box<?> { }                 // ❌ 错误：声明头不能用 ?
List<?> list;                    // ✅ 通配符实参
List<? extends Number> numbers;  // ✅ 上界通配符
List<? super Integer> integers;  // ✅ 下界通配符
```

**身份：通配符实参**（既不是形参，也不是具体类型实参，但归入“实参位置”）。

## 8. 方法调用的显式 / 隐式实参

### 8.1 显式实参

```java
Demo.<String>id("a");    // 尖括号紧跟方法名后 → 显式类型实参
```

这是**唯一一种“方法名后出现尖括号”**的情形。

### 8.2 隐式实参（推断）

```java
id("a");   // 不写尖括号，但编译器推断 T = String
```

**重要结论：**

> **不写尖括号 ≠ 没实参。**  
> 编译器推断出的 `String` 依然是**类型实参**，只是没写出来。

### 8.3 方法名前后位置对照

```java
<T> T id(T x) { ... }     // 声明：<T> 在返回类型之前（方法名之前）
Demo.<String>id("a")      // 显式调用：<String> 在方法名之后
```

**同一个泛型方法：声明时类型形参在方法名前，调用时显式类型实参在方法名后** —— 别搞混。

## 9. 继承场景：槽位里的“跨类传递”

### 9.1 形参继续传递

```java
class GenericBox<T> extends Box<T> {
//                   ↑        ↑
//              声明的 T     引用同一 T
}
```

子类 `T` 是**新声明的形参**，传给父类槽位时是**形参引用**。

### 9.2 形参冻结为实参

```java
class StringBox extends Box<String> {
//                       ↑
//                 具体类型实参 String
}
```

子类不引入形参，直接**冻结**父类实参为 `String`。此后 `StringBox` 内部不再有 `T`。

### 9.3 部分传递

```java
class MixedBox<T> extends Box<List<T>> {
//               ↑              ↑  ↑
//          声明 T         槽位填 List<T>，内层 T 是形参引用
}
```

**外层槽位是嵌套类型，逐层递归。**

## 10. 反射视角：运行时怎么拿

泛型大部分擦除，但**声明信息**和**实参信息**在反射中部分可拿：

| API | 拿到什么 |
|---|---|
| `Class#getTypeParameters()` → `TypeVariable[]` | 类**声明**的类型形参 |
| `Method#getTypeParameters()` | 方法**声明**的类型形参 |
| `ParameterizedType#getActualTypeArguments()` → `Type[]` | 参数化类型里的**实际类型实参**（可能是 `TypeVariable`、`Class`、嵌套 `ParameterizedType`、`GenericArrayType` 等） |
| `TypeVariable#getName()` / `#getBounds()` | 形参名字、上界 |
| `Class#getGenericSuperclass()` | 父类的泛型声明（拿到 `ParameterizedType` 或 `Class`） |

**判身份的口诀（反射版）：**

```text
getActualTypeArguments() 拿到的元素：
  是 Class               → 具体类型实参
  是 TypeVariable        → 形参引用
  是 WildcardType        → 通配符实参
  是 ParameterizedType   → 嵌套，继续递归
  是 GenericArrayType    → 泛型数组，继续看组件类型
```

## 11. 易错点清单

1. **`class Box<T>` 里的 `T` 是形参声明，不是实参；外面 `Box<String>` 里的 `String` 才是类型实参。**
2. **`class Box<T> { List<T> list; }` 里的 `T` 是“形参引用”，不是“实参”** —— 槽位是实参槽，但填充物是形参。
3. **`T` 出现两次身份可能不同**：`<T> T get()` 里第一个 `T` 是形参声明，第二个是形参引用。
4. **方法调用不写 `<String>` 也算使用泛型方法** —— 隐式实参由推断得出。
5. **菱形 `<>` 里空着不代表没实参** —— `new Box<>()` 推断出的类型才是实参；但 `Box<> d;` 非法。
6. **通配符 `?` 只能出现在实参槽位**，不能出现在声明头。
7. **基本类型不能作实参**：`Box<int>` 错，应写 `Box<Integer>`。
8. **`enum` 不能声明类型形参**。
9. **类体中出现的类类型参数 `T` 默认是形参引用；但方法/构造器声明头可声明自己的类型形参，可能遮蔽类 `T`。**
10. **同一行可共存“形参引用”和“具体类型实参”**（如 `Pair<X, String>`），逐槽判断。
11. **泛型声明内部不是“只能”填形参引用**；也可以填具体类型、通配符、嵌套类型，身份看填充物来源。

## 12. 速查表 + 口诀

### 12.1 全表速查

| 代码 | 尖括号位置 | 填充物身份 | 判定 |
|---|---|---|---|
| `class Box<T>` | 类名后 | 形参声明 | 声明 |
| `interface Repo<T>` | 接口名后 | 形参声明 | 声明 |
| `<T> T foo(T x)` | 返回类型前 | 形参声明 | 声明 |
| `<T> Box(T t)` | 构造器名前 | 形参声明 | 声明 |
| `List<T>` 在 `class Box<T>` 内 | 类型名后 | 形参引用 | 使用 |
| `Box<String>` 在普通代码 | 类型名后 | 类型实参 | 使用 |
| `Demo.<String>foo()` | 方法名后 | 显式实参 | 使用 |
| `foo("a")` | 省略 | 推断实参 | 使用 |
| `new Box<>()` | 空槽 | 推断实参 | 使用 |
| `List<? extends X>` | 类型名后 | 通配符实参 | 使用 |
| `Map<K, V>` 在声明内 | 类型名后 | 形参引用 × 2 | 使用 |
| `Map<String, List<Integer>>` | 类型名后 | 实参 + 嵌套 | 使用 |

### 12.2 判断口诀（修正版）

> **声明头里起名字，使用处尖括号填东西。**  
> **类 / 接口 / record 名后，方法返回类型前，构造器名前——只在这 4 处声明。**  
> **槽位固定不变，填充物身份各异：**  
> **声明头尖括号里的类型变量是形参声明；使用处能追溯到类型参数声明的标识符是形参引用；具体类型是类型实参；`?` 系列是通配符实参；空 `<>` 交给推断；嵌套 `<...>` 逐层递归。**

### 12.3 一句话总复习

> **形参是“占位符名字”，只在声明头诞生；实参是“填进去的东西”，可以是具体类型（类型实参）、通配符（通配符实参）、或推断结果；而在泛型声明内部，用形参引用 `T` 站在实参槽位里占位 —— 它是引用，不是实参。**

## 附录：综合练习自查

试着给下面每处标注 `<T>` / `<...>` 的身份：

```java
class Bag<T> {                        // A. ______
    List<T> items;                    // B. ______
    Map<T, List<String>> index;       // C. ______
    <U> U add(U u, List<T> xs) {      // D. ______
        Bag<U> b;                     // E. ______
        return u;
    }
}

class Main {
    Bag<String> a;                    // F. ______
    Bag<List<Integer>> b;             // G. ______
    Bag<? extends Number> c;          // H. ______
    Bag<String> d = new Bag<>();      // I. ______

    void use(Bag<String> bag) {
        bag.<String>add("x", null);   // J. ______
    }
}
```

### 参考答案

- **A**：形参声明 `T`
- **B**：形参引用 `T`（`List` 槽位填形参）
- **C**：`Map` 两个槽位分别填 `T`（形参引用）和 `List<String>`（嵌套，`List` 槽位填 `String` 类型实参）
- **D**：`<U>` 是形参声明；`List<T>` 里的 `T` 是形参引用（引用外层类声明的 `T`）；返回类型 `U` 是形参引用
- **E**：`Bag` 槽位填 `U`（形参引用，引用方法声明的 `U`）
- **F**：`Bag` 槽位填 `String` → 类型实参
- **G**：`Bag` 槽位填 `List<Integer>`（嵌套参数化类型，内层 `List` 槽位填 `Integer` 类型实参）
- **H**：通配符实参
- **I**：变量声明 `Bag<String>` 中的 `String` 是类型实参；`new Bag<>()` 的菱形由目标类型推断为 `String`，是推断实参
- **J**：方法名后尖括号 → 显式实参 `String`
