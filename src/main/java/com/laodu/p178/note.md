# Java 类加载与对象创建完全解析笔记

## 📌 核心心法：区分“两个视角”与“两类东西”

* **两个视角**：**源码视角**（你写的 `.java` 文件） vs **JVM 视角**（编译后的字节码）。你之前所有的别扭，都是因为混用了这两个视角。
* **两类东西**：
  * **类（Class）**：模板。类加载处理的是模板。
  * **对象（Object）**：实例。创建对象处理的是具体实体。

---

## 一、 类加载全流程（模板的诞生）

当我们写了一个类，里面包含静态变量、静态代码块。JVM 是如何把它加载进来的？

### 1. 加载（Loading）

JVM 找到 `.class` 文件，读进内存，生成一个 `Class` 对象。此时，**什么都不赋值**。

### 2. 链接（Linking）

链接分为三个子阶段，这里藏着你的第一个疑问。

#### 2.1 验证（Verification）

检查字节码是否合法，防止安全隐患。

#### 2.2 准备阶段（Preparation） —— 💡【疑问解答区】

JVM 给静态变量**分配内存**并赋初始值。

* **普通静态变量**（`static int a = 10;`）：赋“零值”（`a = 0`）。
* **VIP 通道（编译期常量）**：如果是 `static final` 修饰的**字面量**（如 `static final int A = 10;`），JVM 在这里**直接赋真实值 `10`**，而不是 0。

> **❓ 你的疑问1：意思是准备阶段如果是字面量常量，就直接赋值而不是赋默认值？？？**
> **✅ 完全正确！** 这是 JVM 为编译期常量开的 VIP 通道。
> **❓ 你的疑问2：用到的地方直接是该字面量？这样设计是否多余？**
> **✅ 对！且不多余。** 编译器在编译时，只要看到别的地方用了 `类名.A`，就直接替换成数字 `10`（这叫“内联替换”）。既然准备阶段就定死了，所以准备阶段就直接赋 `10`。这样设计是为了极致的性能（连类都不用加载就能用）。
> **⚠️ 致命坑**：如果你改了 `A=20`，但没重新编译调用方，调用方还是拿 `10`，因为编译时已被写死。

#### 2.3 解析（Resolution）

把代码里的符号引用（比如 `Test.a`）转换为内存地址的直接引用。

### 3. 初始化阶段（Initialization） —— 执行 `clinit`

此时进入 JVM 视角的 **类构造器（`clinit`）**。
JVM 会把**静态变量的显式赋值**和**静态代码块**，按**源码从上到下的顺序**打包成一个方法，名字叫 `clinit`。

**⚠️ 箭头的含义解读（你提供的图片）：**

> “注意：在执行静态代码块之前，所有的static修饰的变量都已经有默认值了。”

* 因为准备阶段已经给所有静态变量分配了内存（哪怕是零值），初始化阶段只是去执行“修改内存值”的动作。

> **❓ 你的疑问3：用到一个类就会类加载吗？多次使用这个类又会如何？**
> **✅ 并不是用到就立刻初始化。** JVM 规定：首次**主动使用**时，才触发初始化。
>
> * **主动使用**：`new` 对象、访问非常量静态字段、调用静态方法、反射等。
> * **被动使用**：访问 `static final` 编译期常量（不触发初始化）、创建数组（`new A[10]`）、通过子类访问父类静态字段。
> * **多次使用**：同一个类加载器下，类只会被加载一次，`clinit` 只会被执行一次。之后复用已有的 `Class` 对象。

## 二、 对象创建全流程（实例的诞生）

执行 `new Child()` 时，在 JVM 视角发生了哪些事？

### 1. 分配内存与赋默认值

JVM 在堆里分配内存，此时对象里所有的实例变量（不管父类子类），统统赋零值（`0`、`null`、`false`）。

### 2. 执行 `init` 方法（实例构造器） —— 你的第二个疑问区

JVM 会把**调用父类构造器（`super()`）**、**实例变量显式赋值**、**实例代码块**、**构造方法体**打包成一个方法，叫 `init`。

> **❓ 你的疑问4：从0开始讲，构造方法在最后，为什么声明的变量访问不到？**
>
> ```java
> class Test {
>     Test() {
>         System.out.println(b); // 报错！非法前向引用
>     }
>     final int b = 20; 
> }
> ```
>
> **✅ 解答：这不是 JVM 运行顺序问题，而是编译期规则！**
> 虽然 `b = 20` 在执行顺序上确实发生在构造方法体之前（JVM `init` 规则），但这**不是编译期就能确定的**。Java 编译器死板地规定：**在成员变量声明之前，不允许使用该变量。** 你想访问，必须把 `b` 的声明挪到构造方法前面。

## 三、 继承的介入（打破你的“别扭”与 `super()` 之谜）

你之前觉得别扭，是因为“构造方法永远是最后”这句话，在加入了继承之后，需要重新定义。

### 1. 真实的 `init` 内部顺序

在 `init` 方法中，执行顺序是极其死板的：

1. 调用父类 `init`（也就是 `super()`）。
2. 执行本类实例变量显式赋值。
3. 执行本类实例代码块。
4. 执行本类构造方法体（你写的代码）。

### 2. 深入剖析 `new Child()` 全流程

看这段经典代码：

```java
class Parent {
    int p = 10;
    { System.out.println("父类实例代码块"); }
    Parent() { System.out.println("父类构造方法体"); }
}

class Child extends Parent {
    int c = 20;
    { System.out.println("子类实例代码块"); }
    Child() {
        // 隐式 super();
        System.out.println("子类构造方法体");
    }
}
```

**执行 `new Child()` 的真实时间线：**

1. 分配内存，所有变量（`p` 和 `c`）赋默认值 `0`。
2. 进入子类的 `init` 方法。
3. 子类 `init` 的第一步是 `super()`。**这就像一道传送门，把控制权交给了父类。**
4. **进入父类的 `init` 方法：**
   * 父类实例变量赋值：`p = 10`
   * 父类实例代码块：打印“父类实例代码块”
   * 父类构造方法体：打印“父类构造方法体”
5. **父类 `init` 执行完毕，回到子类 `init`，继续往下走：**
   * 子类实例变量赋值：`c = 20`
   * 子类实例代码块：打印“子类实例代码块”
   * 子类构造方法体：打印“子类构造方法体”

> **❓ 你的疑问5：因为执行了 super() 进入父类构造方法...这段和之前说的不太一样，很别扭。**
> **✅ 解开别扭：** “构造方法永远是最后”这句话在**单个类的范围内**是正确的。
> 但是，子类的实例变量赋值和子类实例代码块，被硬生生卡在了“父类构造方法体之后”和“子类构造方法体之前”。隐式 `super()` 像一把钥匙，插在子类构造方法体的最前面，打开了父类初始化的全套流程，父类走完，子类才继续走。

> **⚠️ 继承中绝对不要踩的坑**：不要在父类构造方法里调用被子类重写的方法，且该方法使用了子类的实例变量。因为此时子类的实例变量还没赋值（只有默认值 0）。

## 四、 `final` 关键字的深度解析（终极区分）

你之前觉得最绕的地方，我们用一张表彻底钉死。

> **核心口诀：`final` 管“能不能改”，`static` 管“属于类还是对象”，是不是“编译期常量”管“会不会触发类初始化”。**

| 代码写法                                          | 属于类还是对象 | 准备阶段（赋什么值？）                  | 初始化阶段（做什么？）        | 使用它触发类初始化吗？           |
| :------------------------------------------------ | :------------- | :-------------------------------------- | :---------------------------- | :------------------------------- |
| `final int a = 10;`                             | 实例变量       | 对象分配后赋零值 `0`                  | 执行 `init`，赋值 `10`    | 不涉及类初始化                   |
| `static int a = 10;`                            | 静态变量       | 赋零值 `a = 0`                        | 执行 `clinit`，赋值 `10`  | 会                               |
| `static final int A = 10;`                      | 静态变量       | **VIP通道：直接赋真值 `10`**    | 无（不进 `clinit`）         | **不会**                   |
| `static final String S = "abc";`                | 静态变量       | **VIP通道：直接赋真值 `"abc"`** | 无（不进 `clinit`）         | **不会**                   |
| `static final String S = new String("abc");`    | 静态变量       | 赋零值 `S = null`                     | 执行 `clinit`，赋新对象     | 会                               |
| `static final int R = (int)(Math.random()*10);` | 静态变量       | 赋零值 `R = 0`                        | 执行 `clinit`，计算真实值   | 会                               |
| `static final Integer I = 10;`                  | 静态变量       | 赋零值 `I = null`                     | 执行 `clinit`，自动装箱赋值 | 会（因为是包装类型，非基本类型） |

**针对 `static final` 的终极总结：**

* **编译期常量**（基本类型/String 字面量）：准备阶段直接赋真值，使用时不触发类初始化。
* **非编译期常量**（`new`、方法调用、包装类型）：准备阶段赋零值，初始化阶段（`clinit`）才赋真值，使用时会触发类初始化。

---

## 五、 终极总结口诀（极简复习）

1. **类加载**：加载 -> 验证 -> **准备（默认值/常量真值）** -> 解析 -> **初始化（`clinit`按源码顺序执行）**。
2. **对象创建**：分配内存（默认值） -> **执行 `init`（先 `super()`，再实例变量，再实例代码块，最后构造方法体）**。
3. **`static final` 常量**：字面量准备期直接赋真值（内联替换，不触发类初始化）；非字面量走常规初始化流程。
4. **继承体系**：先父后子。父类的实例初始化（变量、代码块、构造方法）永远优先于子类的实例变量初始化。
5. **前向引用**：别在变量声明之前使用它，这是编译器的死规矩，跟 JVM 执行顺序无关。

把这份笔记吃透，面试或者写业务代码时遇到任何静态、实例、继承、`final` 的组合，你都能在脑海里瞬间画出它的执行时间线。
